# Idea — 阶段 7：笔记引用闭环

**阶段目的**：写笔记、描述任务或追加评论时，可以直接引用已有笔记；打开笔记时，能找回使用它的工作上下文。

**阶段产出**：三处统一的 `[[` 搜索与插入、点击打开笔记、自动计算且按来源去重的「被引用」。

**状态（2026-10-15）**：**主体功能已完成，非验收类必修项只剩「绑定 ID 失效时禁止按同名标题接管」**。返回来源页面及日期仅为不阻塞阶段 8 的可选体验；外部移动后的跨文件链接自动维护、精确滚动/光标恢复等过度设计不再实施。macOS 实机验收仍待完成，详见 [分项完成标准](proposal.md#完成标准)。

## 为什么需要笔记引用

现有 Notes 已能承载完整技术文档，Task 也能明确关联 Note，但正文中的知识引用还没有统一体验。写《湖仓架构设计》时需要引用《Doris 部署规划》；执行验证任务时，描述和评论也需要指向同一份规划。

全局标签用于聚合主题，不能表达「这段内容引用了哪篇文档」。让引用在写作过程中自然形成，可以减少重复说明，也让长期文档与实际工作连接起来。

## 用户只需要记住一个动作

> 想引用一篇已有笔记，就输入 `[[`。

在笔记正文、任务描述、任务评论中输入 `[[`，搜索并选择笔记。阅读时点击名称即可打开；目标笔记自动显示引用它的笔记或任务，无需手动维护第二条反向关系。

Task 描述和任务评论仍然是纯文本。引用只是可识别、可跳转的文本片段，不要求用户学习 Markdown，也不引入富文本编辑器。

## 只保留三个能力

1. **引用**：输入 `[[` 搜索已有笔记，选择后插入；同名笔记通过路径区分。
2. **跳转**：点击引用打开真实目标，并能返回原来的写作或任务上下文。
3. **找回来源**：笔记底部显示默认折叠的「被引用 · N」；无来源时不显示。同一任务的描述和多条评论只算一个来源。

**Task/Activity 的 `[[名称]]` 一旦绑定真实 Note ID，标题改名不改变目标身份**；无绑定时只有标题唯一匹配才可解析。Notes 正文采用标准 Markdown 相对链接，用户在应用外移动或重命名文件路径后可能导致这些链接失效：**不自动跨文件重写**，保留原文并提示手动修复，不能猜测另一篇同名笔记或自动创建空笔记。

## 与现有产品的关系

沿用 Today / Tasks / Notes 三个导航和单 Vault。**当前源码**的任务评论仍通过带 `task_id` 的 Memo 实现；阶段 8 将统一为内嵌 Activity，不增加新导航。Notes 仍单列浏览、全主区域编辑。

统一操作，不强求统一存储：Note 正文保存标准 Markdown 相对链接；Task 描述与任务评论保留 `[[笔记名]]` 文本，并持久化足以辨认真实目标的正向引用信息。被引用来源从文件计算，不写回目标笔记。

兼容现有 Task 的 `note_ids` 关联，不清空旧数据，不自动把旧关联复制进描述。具体实现与待验收差异见 [proposal](proposal.md)。[阶段 2 schema](../02-foundation/schema.md) 当前描述**阶段 8 待实施的目标格式**；本阶段实现仍按旧 Memo 文件模型运行。

## 本阶段边界

只做整篇笔记引用。不做关系图谱、关系管理页面、悬停预览、标题级或块级链接、内容嵌入、未链接提及识别；不新增独立关联按钮或强制整理动作。Today 今日 / 当日记录（当前实现为 Memo、阶段 8 改为 Activity）的引用输入、行内编辑与点击跳转已实现。不做外部移动后的自动维护、跨文件批量重写与重试，也不实现来源滚动/编辑光标的精确还原；来源页面/日期恢复可在轻量方式可行时再考虑，不阻塞阶段 8。

遵循 Less is More / Record Once / Local First：文档保持可直接读取，记录只有一份，引用能力离线可用。
