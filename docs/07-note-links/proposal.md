# Proposal — 阶段 7：笔记引用闭环

## 范围与当前基础

承接 [idea](idea.md)，以[原对话](chatgpt-conversation://6ace2abb-13d8-83ea-b8b0-c394cd92b9b5) 最后一轮 Less is More 收敛为基线：笔记正文、任务描述、任务评论统一输入 `[[`，点击打开笔记，自动显示被引用来源。

> **实施状态（2026-10-15 静态复核）**：笔记引用的主体功能已经落地：Go 解析/索引、持久化 `note_refs`、Notes/Task/Today `[[` 交互、点击跳转与“被引用” UI；已有 Go 自动化测试覆盖部分存储和去重。**本次没有重新执行测试或 macOS 实机验收。** 已确认的缺口：Note 源文件在应用外移动后不自动维护其他源中的相对链接；返回没有完整恢复光标/滚动位置；前端已绑定目标失效后仍有按同名标题回退匹配的风险（见下文未完成项）。

本方案最初作为阶段 7 新增路线；**目前主体功能已有源码实现**，阶段 4、5 的历史交付记录不变，也不新增主导航。以下实施步骤保留作为设计追溯，后续以末尾逐项验收清单为准。

## 实施顺序

1. **先验证存储与编辑往返**：用同名笔记、跨目录笔记验证 Vditor 插入相对链接；确定纯文本引用如何持久化真实 Note ID。任何字段扩展先写入 [schema.md](../02-foundation/schema.md)，补充序列化、重启重建、外部编辑兼容验证，再进入 UI 实施。
2. **建立最小引用解析与查询**：复用现有 Note ID、路径索引和安全写入；覆盖 Note 正文、Task 描述、任务评论，以及已有 `note_ids`。不建设通用关系实体或关系数据库。
3. **完成三处搜索与插入**：共用笔记候选和键盘操作，适配现有 Vditor 与纯文本输入框；不更换编辑器。
4. **接入点击与返回**：笔记进入全主区域；任务来源回到现有详情面板，保留草稿和来源上下文。
5. **展示被引用来源**：默认折叠、按来源去重、不显示摘要或描述/评论分类。
6. **验证引用维护与文件安全**：改名、移动、删除、外部编辑、冲突、重扫与重启；通过后回填完成标准，记录 macOS 实机结果。

第 1 步必须解决目标身份持久化，不能只保存标题、把不可恢复的对应关系留在内存里，再用 UI 宣称同名与改名问题已解决。

## 输入、阅读与跳转

### 三处共用 `[[`

- 输入 `[[` 后在光标附近显示笔记候选，继续输入按标题搜索；只返回当前 Vault 的已有 Note。
- 候选显示标题；同名时补充 Vault 内相对路径，不增加文件树或目录导航。
- 方向键选择、回车确认、鼠标点击插入；Esc 关闭，不改动已输入文本。没有结果时显示「没有找到笔记」，不提供自动创建。
- 中文输入法组合输入期间不拦截回车；补全关闭后恢复普通换行行为。列表可通过键盘操作，焦点与选中态可见。
- 选择后只替换当前引用片段，不覆盖其它文本；引用移除或编辑后随原内容一起保存。

Note 选择后插入标准 Markdown 相对链接，源码仍可直接读取和编辑。Task 描述与任务评论选择后保留 `[[笔记名]]` 语法，阅读时显示可点击名称；其余文字、换行与 Markdown 符号按纯文本显示，不解析标题、加粗或表格。

原规划仅覆盖上述三处；经用户实测反馈，补充 Today「今日 / 当日记录」的创建、行内编辑与时间线阅读，包含独立 Memo。沿用 `note_refs` 绑定，正文保持纯文本。任务标题、标签名称、快速创建任务输入和全局搜索框不增加引用补全；不把「多行输入」泛化成所有字段都支持。

### 跳转与草稿

阅读状态点击引用进入目标 Note，全主区域展示，不开新窗格或常驻关系栏。编辑状态保留现有光标与文本选择行为；不要求额外开发编辑中的行内点击或 ⌘ 点击能力。

返回恢复来源 Note 的位置，或来源页面的日期、筛选、滚动与任务详情。打开另一篇 Note 前按 D19 flush 自动保存；Task 描述、未提交评论及 Today 新记录 / 行内编辑有草稿时沿用保存 / 放弃 / 取消规则。保存失败、冲突或用户取消时留在来源，不能用跳转丢掉草稿。

已有普通外部链接沿用现有处理，不转成笔记引用。失效引用保留文字并提示「笔记不存在或已移动」，不打开空白编辑页、不自动新建笔记。

## 被引用来源

在 Note 正文下方显示「被引用 · N」，默认折叠，展开后为单列来源名称；没有来源时整个区域隐藏。不显示引用片段摘要，不按笔记、描述、评论分组，不统计正文中出现的次数。

| 原始引用 | 显示来源与计数 |
|---|---|
| 同一 Note 多次引用目标 | 一条来源 Note，计 1 |
| 同一 Task 的描述和多条评论引用目标 | 一条来源 Task，计 1 |
| 同一 Task 的 `note_ids` 与正文引用重合 | 同一条来源 Task，仍计 1 |
| 两个不同 Task 引用目标 | 两条来源 Task，计 2 |

去重使用来源实体的类型和稳定 ID，不使用名称。点击 Note 打开该笔记；点击 Task 打开现有任务详情，不另做评论定位或高亮。列表按来源标题排序，同名来源补充路径或必要辨认信息。

引用自身不计为被引用来源。父 Task 已删除的评论仍保留 Memo 文件与正文；该引用不显示成一个可打开的 Task 来源，不增加独立 Memo 来源类型。若评论改关联另一 Task，则重新归并到新的任务。

只有保存成功的内容进入被引用查询。新增、修改、删除来源、删除引用和外部文件刷新后更新结果；草稿不提前增加计数。所有数据可通过重新扫描恢复，无需用户维护反向关系。

## 存储与正确性约束

数据格式的单一来源仍为 [阶段 2 schema](../02-foundation/schema.md)。下表规定本阶段必须验证的行为，不在这里另建字段规范；新增字段的精确名称、编码和兼容规则由实施第 1 步在 schema 中落定。

| 内容 | 正文保存方式 | 目标识别要求 |
|---|---|---|
| Note | 标准 Markdown 相对链接，如 `[Doris 部署规划](./doris-deployment.md)` | 解析为 Vault 内真实 Note；路径变更后维护引用 |
| Task 描述 | 纯文本 `[[Doris 部署规划]]` | 持久化到实际 Note ID 的绑定；不能靠标题重新猜测 |
| 任务评论 | 同上，仍只有一份 Memo | 绑定随评论源文件保存，索引丢失后可恢复 |

### 正向信息与可重建索引

纯文本中的显示名称不是唯一标识。选择候选时确定真实目标，必要的正向绑定随源文件 Frontmatter 持久化；不能只新增一个 `note_ids` 集合就宣称能区分正文里两处同名引用。引用编辑、删除、重复出现以及重启后仍必须定位正确片段和目标。

Note 的正文链接保持标准 Markdown，可在外部编辑器使用。实现时验证相对路径到 Note ID 的对应及改名/移动维护；若需要持久化辅助正向绑定，也统一在 schema 中定义，不在正文塞隐藏状态块，不引入另一份业务数据库。

「被引用」是上述正向信息的查询结果，不写进目标 Note 的 Frontmatter 或正文，不自动创建 B → A 的第二条链接。索引可删除重建；承载正向信息的源文件和 `.pata/plans/` 始终是须备份的业务数据。

手工输入但未选择候选的 `[[名称]]`，仅在唯一匹配已有 Note 时允许解析；同名或无匹配时保留原文并提示用户重新选择。外部编辑导致绑定无法确定时，同样不能擅自指向某个同名目标。

Note 中只将实际指向 Vault 内 Note 的正文链接纳入查询；普通 URL、图片、代码块与行内代码示例不计为笔记引用。纯文本描述和评论不解析普通 Markdown 链接；转义后的引用语法应可作为字面文字保留，规则在 schema 中一并明确。

### 改名、移动与删除

- 持续使用已有 Note 稳定 ID；修改标题不改变目标身份，不强制批量改写用户自定义的链接显示文字。
- 目标或来源 Note 在 Vault 内移动时，重新计算受影响的相对路径；不为了本阶段新增文件管理页面。
- 应用内受控修改和可可靠识别的外部移动都应维护引用；外部改名保留 ID 时利用既有身份识别。全量重扫及重启后的行为也必须验证，不能只依赖上一轮内存路径。
- 无法可靠确认目标、ID 冲突或文件已离开 Vault 时保留原文并报告失效，不靠同名推断。不静默改写 Vault 外文件。
- 删除目标 Note 后保留来源正文与正向引用，显示失效状态；之后新建同名 Note 不能自动接管旧引用。
- 链接维护涉及多个源文件时逐个执行已有版本检查与安全写入；存在草稿或外部冲突的文件不能被覆盖。部分失败时报告待修复来源，保留可重试信息，不能假报全部成功。

### 兼容现有能力

现有 `Task.note_ids` 继续读取、保存和通过原有能力管理，并作为 Task 来源计入被引用；不批量迁移、不自动复制成描述引用，不把删除正文引用解释为删除另一条显式关联。原有选择器是既有兼容能力，本阶段不再为正文或评论新增独立「关联笔记」按钮。

Task 描述沿用 [D25](../01-validate/decisions.md) 的纯文本规则，仅增加笔记引用识别。任务评论本阶段按纯文本输入与阅读，旧 Markdown 符号原样保留，不进行格式清洗；Today 独立 Memo 同样支持引用，其余行为沿用阶段 3，独立 Memo 不新增为「被引用」来源类型。

Notes 自动保存、Task/Memo 手动保存、未知 Frontmatter 字段保留、外部修改冲突保护均沿用已有规则。引用不改变标签继承、DayPlan、due 或任务状态事件，也不复制 Memo。
