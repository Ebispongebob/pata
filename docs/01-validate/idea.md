# Idea — 阶段 1：确认产品与交互

**目标**：不用开发完整软件，先把“为什么做、做什么、不做什么、如何使用”达成一致。

**阶段产出**：产品基线、交互流程、页面规范、可离线运行的 UI 概念原型。

## 产品动机与原则

## 痛点

使用者同时需要：早上快速安排工作、跟踪数日甚至数周的任务、随手记下技术验证与讨论、编写长篇技术方案、在周/月末整理成果。传统知识库和任务管理 App 往往各有一套复杂的分类、日期和操作流程，导致同一件工作被重复输入。

## 产品假设

当产品只有 Today（当下）、Tasks（行动）、Notes（文档），并通过轻量 Memo 记录过程、全局 Labels 关联主题时，足以覆盖绝大部分日常工作。

## 北极星原则

1. **Less is More**：删除一个功能后若核心工作流仍通畅，就先不做。
2. **Record Once**：任务进展只记一处，Today 和标签页只是视图。
3. **Markdown First**：纯文本可读、可编辑、可备份、可供已有 Agent 使用。
4. **Local First**：不依赖后端服务、云账户、网络。
5. **No Ritual**：不要求每天写工作日志、清空 Inbox 或下班总结。

## 不试图解决的问题

团队协作、企业流程、CRM、全能知识管理、双向链接知识图谱、综合日历、多端实时同步以及内置 AI 平台。

## 真实工作节奏

## 用户真实节奏

早晨需要清楚今日重点；白天有计划任务也有临时讨论；长任务跨天，需要累积过程；每周/月末才需要系统回顾。正式总结不必成为每天的义务。

## 关键原则

- “计划”是选择已有任务，不是复制一份 Todo；用当日计划顺序表达推进次序，不增加任务优先级。
- “记录”是顺手追加有价值的信息，不要求完整流水账。
- “复盘”是读已有事实后提炼，而不是回头补日志。

## 视觉与交互方向

参考 Flomo 的轻量列表、标签导航、快速浏览，但不复制其以短 Memo 为中心的全部工作模式：这里的 Notes 需要能写很长的技术 Markdown。

视觉原则：浅色、克制、舒适间距、低密度信息、尽量少的分割线和面板。产品使用重心是阅读与写作，而不是“管理管理系统”。
