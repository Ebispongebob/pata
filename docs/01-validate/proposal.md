# Proposal — 阶段 1：确认产品与交互

## 本阶段任务

1. 固定 V1 的三入口、三内容实体及全局标签含义，明确不做的功能。
2. 将早晨规划 → 工作中推进与 Memo → 文档沉淀 → 周/月回顾串成无重复写入的流程。
3. 完成 Today / Tasks / Notes / 标签聚合的页面状态与返回规则。
4. 用离线 UI 原型验证导航、单列 Notes、独立及关联 Memo 的体验。
5. 补充 [macOS 27 体验准则与 Magpie 源码实现参考](macos-native.md)，把原生窗口交互和视觉材质区分为必须验证与可回退增强。

## 本阶段完成标准

- [x] 所有主页面交互可从原型演示；尚不宣称真实持久化。
- [x] Notes 浏览不出现“文件树 + 列表 + 编辑器”三列结构。
- [x] 标签点击行为始终为 Task + Note + Memo 全局聚合。
- [x] MVP 边界冻结：CLI / MCP / AI 集成不开发。
- [x] 已形成 [macOS 原生体验验证清单](macos-native.md)：原生交通灯、HiddenInset、拖动/no-drag、系统主题与可访问性；阶段 2 实机 Spike 执行，阶段 1 只确定规范。

## 产品基线

## 一句话

早上安排今天的事，工作中顺手留下记录，完成后沉淀成果，需要时自然回顾。

## 用户与平台

单人使用，首发 macOS。主要工作为长期技术设计/开发/验证，已有 Pi 等外部 Agent 能直接读取本地工作文件。无需内置 AI。

## 顶层导航

1. **Today**：今日计划 + 当日时间线；可查看历史日期。
2. **Tasks**：全量任务管理和跨天跟踪。
3. **Notes**：单列笔记卡片 + 全宽 Markdown 编辑。

侧栏展示**全局扁平 Labels**，点击后进入按 Task / Note / Memo 分组的聚合结果，不因当前页面不同而改变含义。搜索为全局操作，不新增一级入口。

## 内容与记录

- **Task**：带状态、优先级、可选截止日期、标签、正文、关联笔记的工作项。
- **Memo**：内容 + 时间 + 可选 `task_id`；有 `task_id` 时即为任务评论，无时即独立记录。
- **Note**：标题 + Markdown 长文 + 可选标签，承载技术方案、POC、会议纪要、复盘成果。
- **DayPlan**：内部日期 → 有序任务 ID 列表；不是 Daily Note，也不等于 Due。

## 主要场景验收

- 早晨：从已有任务池选择 2–5 项放入 Today 并排序；无需复制任务。
- 执行：打开任务查看背景、追加 Memo、引用外部代码链接或 Note，跨天不丢过程。
- 临时事：Today 快速 Memo，无需指定项目或标签。
- 文档：从 Notes 打开长篇文档，用完整主内容区编辑。
- 回顾：历史 Today、全局标签及搜索能重建过程；周/月文档可由外部 Agent 读取 Markdown 后撰写。

## 明确不做（MVP）

Projects、Areas、Inbox、Daily Note、日历/周视图、子任务、强制日终总结、看板、重复任务、录音转写、AI 集成、CLI、MCP、服务端 API、插件、云同步、SQLite 作为业务真相来源。

## 非功能要求

- 不联网也可启动及读写。
- 外部编辑 Markdown 后 App 可检测并刷新；不能默默覆盖未保存的编辑。
- 协议独立于具体 UI 框架；数据可迁移。
- 核心操作无需为标签、归档、文件夹、项目补齐额外步骤。

## 待真实使用验证

独立 Memo 频率与搜索体验；Wails v3 稳定性；Vditor 所见即所得的 Markdown 兼容性；任务历史事件的最小实现；跨工具并发写入行为。

## 端到端工作流

## 1. 早上 Today

打开 Today → 查看今日列表和可选的昨日未完候选 → 从全量 Tasks 中加入任务 → 拖拽排序。已被安排过的 Task 可以再次安排到另一日。**不自动延续昨日计划**。

## 2. 工作中

点击任务 → 看描述 / 关联文档 / 历史 Memo → 更新 Todo/Doing/Done；遇到关键进展，写一条关联 Memo。

临时会议或想法 → Today 输入独立 Memo（无标题、无强制标签）；有必要再关联 Task 或形成长篇 Note。

## 3. 文档沉淀

Notes 单列搜索/标签浏览 → 打开 Note 在完整主区域编辑正文 → 可从 Task 详情明确关联该文档；同标签并不意味着自动关联。

## 4. 历史与复盘

Today 选择历史日期可见该日 DayPlan 和时间线。时间线来源：Memo（独立与任务关联）+ 自动任务完成/重新打开事件。

周/月末按时间、主题、任务筛选内容 → 手动或由外部 Agent 总结 → 保存一篇 Markdown Note。**App 不强制生成，也不内置 LLM。**

## 5. 数据写入原则

记录任务进展只新增一次 Memo；UI 通过时间、任务 ID 和标签动态查询。

## 边界示例

- 今日截止但未排入 Today：Task 依然显示 Due；可在 Tasks 内筛选，不自动进入今日计划。
- 今日已计划但未完成：今日历史中仍可查，明天不会自动出现。
- 完成任务但没有 Memo：自动事件照样记录完成时间。
- 完成后重新打开：保留已发生的完成事件，不篡改历史。
- 独立 Memo 后来关联 Task：内容不复制，仅补 `task_id`。

## UI 信息架构

## 整体窗口

- 一条左侧主导航：Today / Tasks / Notes；其下是**全局标签**和快捷搜索入口。
- 一块主要内容区域，布局随选中的主入口切换。
- 不增加右侧详情常驻栏，也不在 Notes 中增加文件树列。

## 页面行为

| 入口/动作 | 主内容区域 | 返回 |
|---|---|---|
| Today | 日期、今日计划、今日记录/快速 Memo | 不适用 |
| Tasks | 可筛选任务列表 | 任务详情返回任务列表 |
| Notes | 单列卡片流 | 编辑页返回笔记列表 |
| 点击侧栏标签 | 单列按 Task / Note / Memo 分组结果 | 点主导航返回对应页面 |
| 全局搜索 | 轻量覆盖层或主区域结果 | 关闭后保留原页面 |

## Notes 的硬约束

**没有“文件树 + 笔记列表 + 编辑器”三列结构**。Notes 浏览只占一个主区域；点击后编辑器占用同一个主区域。左侧主导航不消失。

## Memo 的位置

不是主入口。Today 的快速输入和 Task 详情的评论输入都写同一种 Memo；Today 时间线显示两者，不能复制记录。

## 详情跳转

从标签聚合或 Today 时间线打开关联 Task/Note，保留可回退的位置；浏览/编辑页支持返回。

## 原型

- [`prototype/index.html`](prototype/index.html) — 本地浏览器直接打开；无网络和构建依赖。
- `prototype/screenshots/*.png` — 由本地浏览器渲染的页面截图。
- 这是**布局/交互模拟**，所有数据保存在浏览器内存中，刷新会恢复示例；不等于 App 完成。

## 标题与 Markdown 正文

为了避免 Frontmatter `title` 和 Markdown 首行同名一级标题在 UI 中显示两次，渲染时可折叠相同首行标题；源文件保持原样。
