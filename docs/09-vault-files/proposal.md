# Proposal — 阶段 9：专属 Vault 与统一资源引用

> **状态：设计已确认，尚未实施。** 阶段 8 Activity 重构是前置条件。本阶段只规划后续实现；没有修改源码、运行测试或验证 macOS GUI。详见 [idea](idea.md)。
>
> **唯一存储规范**：文件目录与 Markdown 结构以 [阶段 2 Schema](../02-foundation/schema.md) 为准。本方案只写实现和验收，不另定义一份独立协议。

## 一、产品边界

- 啪嗒是**以记录为中心**的本地工作应用，不是通用文件管理器；保留 Today / Tasks / Notes 三主导航。
- Vault 是啪嗒专属的数据工作空间，**不是对用户任意 Markdown 目录的接管**。只索引约定的业务目录；`notes/` 可包含子目录，`files/` 可保存原始文件。
- 用户在 Today 的独立 Activity、Task Activity 与 Note 中导入及引用文件；**不要求每个文件都必须保持引用**。一个文件可以同时被多条记录引用。
- 现有 `[[` 是统一**搜索选择入口**：既有 Note 和已导入文件都可选择；不是新增实体关系管理器。Note 的稳定 ID 绑定保持不变，File 不额外分配业务 ID。
- 文件可以通过全局搜索**文件名**找到，即使没有任何记录引用；命中的 Activity/Note 同样按现有定位方式打开。
- `files/` 永远保留原始二进制内容。用户删除 Activity、Note 或某个引用，不连带删除附件。

## 二、目录与归属

```text
PataVault/
├── notes/            # Markdown Note；允许子目录
├── tasks/            # Task 与所属 Activity
├── plans/            # DayPlan 与独立 Today Activity
├── files/            # PDF / DOCX / PPTX / 图片等原始文件
└── .pata/            # 可重建索引、设置等内部状态（按需）
```

- **本阶段的 Vault 边界**：扫 Task 只看 `tasks/`，扫 Note 只看 `notes/**`，扫 DayPlan 只看 `plans/`；只在 `files/**` 枚举普通文件资源。根目录的 README、`docs/` 及其他目录不自动进入 Note 列表。
- 文件由目录限定可管理范围，并由实体格式区分 Task、Note、DayPlan。遇到不合规文件按已有文件级保护原则处理；不把未知位置的 `.md` 静默当 Note。
- `plans/` 是用户内容而非缓存：阶段 8 的目标路径直接采用该目录。当前实现可能仍使用 `.pata/plans/`，待阶段 8 改造时处理；阶段 9 不再安排第二次迁移。
- `files/` 中的资源无需 YAML Frontmatter、独立 Markdown 包装、JSON 侧车、标签和系统状态。引用关系从来源正文及相对路径计算；资源不反写被引用数据。
- `.pata/` 不存放用户数据的唯一副本；索引失效可重新扫描构建。

## 三、导入、引用与查看

### 第一次导入

用户在 Today 独立 Activity、Task Activity 或 Note 的输入区域拖入文件，或粘贴剪贴板中的图片/文件：

1. 判断它是否为可访问的普通文件；对图片剪贴板可生成实际图片文件；**不修改或搬走外部源文件**。
2. 复制到当前 Vault 的 `files/`，保留原格式和可识别名称。同名但内容可能不同，**不覆盖**：生成不冲突的名称；第一版不做内容哈希和自动去重。
3. 由 **Go Core** 完成 Vault 内路径验证、安全复制和索引更新；在当前编辑光标处插入指向新文件的 Markdown 相对链接。链接必须相对于**实际宿主 Markdown 文件**计算，不能硬编码 `../files/`。
4. 为避免生成孤儿附件，来源保存失败、输入被取消时，不偷偷向用户宣称插入成功；允许在简单回滚可行时删除本次未正式引用的复制结果，但**不引入异步清理或跨文件事务**。涉及文件已存在、多处复用时不得回滚删除已有资源。
5. 文件导入不改变 Activity 的归属、时间、标签和 Note 的保存机制。

Notes 使用现有 Vditor Markdown 链接与图片能力；Activity/Task 描述仍是**纯文本**，只把识别出的文件链接在阅读时渲染为可点击项，不因此启用通用 Markdown 富文本渲染。Task 描述是否允许首次拖入文件，延续已有纯文本规则并纳入同一实现组件；文件能力首先保证两类 Activity 与 Note。

### 再次引用

- 在已有的 `[[` 候选中同时列出 Note 和 `files/` 下的文件，输入关键字匹配标题/文件名；同名用路径及简短类型图标区分，不增加独立弹窗。
- 选择 Note：保持阶段 7 的身份绑定。Note 正文插入标准 Markdown 相对链接；Task 描述/Activity 使用 `[[名称]]` 和局部 `note_refs`。
- 选择 File：**只插入**标准 Markdown 相对链接（如 `[晋升答辩.pptx](../files/晋升答辩.pptx)`），不再复制文件，也不保存 `file_refs`、File ID 或关系表。
- 对同一份文件多次引用仍只有一个文件；不要求用户预先选择关联 Task 或创建包装 Note。
- 文件的重命名或外部移动可能令相对路径失效：保留用户原文，点击时明确提示；**不追踪 inode/Bookmark，不自动修改其他记录**。

### 点击与预览

- Note：保留已有打开与返回体验；文件：优先使用 macOS 原生 Quick Look / 系统预览能力，提供「在 Finder 中显示」。
- 用户若要编辑 Word、PPT、PDF，交给系统应用；啪嗒不开发内置 Office/PDF 编辑器。
- 禁止通过伪造相对路径读取 Vault 以外的文件、目录遍历与符号链接逃逸；Vault 中已有文件本身不会因点击或预览被改写。

## 四、全局搜索与引用来源

- 扩展 `SearchAll`：除 Task/Note/Activity 内容外，能按名称搜索 `files/**` 资源（可选匹配其 Vault 相对路径）。不解析 PDF/Office 正文、不引入全文索引、OCR 或外部搜索服务。
- 文件名搜索**不依赖是否被引用**：即使唯一引用被删掉，仍能命中文件并直接预览。
- Activity/Note 中出现的文件标题、链接文本与相关自然语言继续归属于**原来的记录**搜索结果；同一个文件可被多条记录引用，不需要为每处引用复制文件。
- 可重建的正向引用索引用于跳转和日后统计来源；文件点击不用强制展示「被引用」来源列表。已有 Note 的「被引用 · N」按 Note/Task 去重行为不能回退；独立 Today Activity 仍不因此增加第四导航。
- 搜索结果含文件类型时采用原有浮层与键盘操作，选择文件直接预览；不引入新的 Files 页面、侧栏分组或专属详情视图。

## 五、安全、兼容与取舍

1. **路径**：标准 Markdown 相对路径与 URL 转义；以宿主的实际文件位置解析并规范化，拒绝越过 Vault 的路径、非法链接与指向外部文件的恶意输入。
2. **写入**：二进制资源复制采用不覆盖目标的安全写入；文件名冲突生成不同目标，错误明确返回。Task/DayPlan 继续使用阶段 8 单文件串行写、冲突检测和原子替换。
3. **读取**：索引可通过有效 Vault 文件重建；解析失败不能触发覆盖/删除原文件。外部编辑造成的失效链接不当作自动清理依据。
4. **删除**：删除一条 Activity/Note/引用只影响原记录或链接，不删除 `files/` 中的文件。用户确需物理整理和删除时使用 Finder。
5. **不扩范围**：不做定时扫描未引用文件、自动清理、inode/Bookmark 追踪、统一 Resource ID、PDF/Office 内容搜索、哈希去重、复杂文件权限管理或同步功能。
6. **暂缓话题**：外部普通 Markdown 放进 `notes/` 的 Frontmatter 接纳规则暂不改变既有行为；未来 Agent 的文件操作经 App Core 的 CLI 接口进入，阶段 9 不开发 CLI/MCP/AI。
7. **旧布局**：阶段 8 尚未实施，目标直接采用根 `plans/`；若本地有旧 `.pata/plans/` 测试文件，应先明确备份与人工处置，不静默丢弃。

## 六、实施顺序

### P9-001 — Vault 目录边界与资源索引

- Go Core 的全量扫描、文件监听、健康检查限定到专属业务目录；不再误把根目录其他 `.md` 当 Note。
- DayPlan 新路径采用阶段 8 已确认的根目录 `plans/`；核对新建 Vault、重启重扫、历史日期读写一致。
- 新增轻量文件资源枚举（路径、文件名、后缀与必要的文件系统属性）；资源不是顶层业务 Entity，无 Frontmatter。
- 保证错误隔离、目录软链接/路径逃逸保护和大小写/同名结果的可预期行为。

### P9-002 — 文件导入与统一 `[[` 引用

- Go Core 提供安全复制/导入、相对路径生成/解析、存在性校验与预览定位所需服务。
- 共用现有 Note 引用组件与 `[[` 候选，只增加 File 候选及选择后的分支；保留阶段 7 Note ID 正向绑定与去重行为。
- 接入 Today Activity、Task Activity 与 Note 的拖入/粘贴和链接插入；纯文本字段仅专门渲染可点击的文件链接，其余 Markdown 保持字面文本。
- 验证空格、中文、括号、同名文件、跨目录相对路径、重复复用、失效链接与未提交草稿保护。

### P9-003 — 全局搜索、原生预览与回归

- `SearchAll` 增加文件名命中、文件类型结果、预览及 Finder 定位操作，不新增一级导航。
- 验证 Activity/Note 中的文件引用文本仍能由正文检索找到；从搜索结果正确回到原 Task 或 Today 日期。
- 回归 Note 现有 `[[` 补全、绑定 ID 失效、防同名误接管、被引用来源，及阶段 8 Activity 保存/删除/索引；完成 Go 测试、TS 测试/构建、macOS GUI 实机验收。
