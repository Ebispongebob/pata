# MVP Acceptance Criteria

- [ ] 用户选择本地 Vault，无需登录或联网。
- [ ] 新建 Task，设置状态、due、标签，保存在规范 Markdown 文件。
- [ ] 将同 Task 安排到多个 Today 日期，不修改 due，也不创建任务副本。
- [ ] Today 按用户顺序显示计划，可移出但不删除 Task；昨日未完不自动移入今天。
- [ ] 为 Task 添加 Memo 后，Task 详情与对应日期 Today 都能看见同一条记录。
- [ ] Today 可创建独立 Memo，不强迫输入标题、标签或关联任务。
- [ ] 完成任务产生时间信息；重新打开不会抹掉过去的完成事实。
- [ ] Notes 单列卡片列表；编辑状态占据完整主区域（无第二层树状导航列）。
- [ ] 全局标签页按 Task、Note、Memo 分组；关联 Memo 通过父任务标签被查到。
- [ ] Note 可显式关联 Task；仅共享标签不等于自动关联。
- [ ] 所有数据可被纯文本工具/外部 Agent 阅读；没有独立业务数据库。
- [ ] 外部修改文件后 UI 更新；与未保存本地修改冲突时禁止静默覆盖。
- [ ] 无强制日记、日终总结、Projects、Inbox、CLI、AI/MCP。
- [ ] 标题栏保留真实 macOS 交通灯，工具栏拖动/no-drag 正确；窗口缩放、全屏、关闭/退出、Dock/菜单栏符合系统习惯。
- [ ] 深色/浅色、系统强调色、键盘焦点、减少动态效果、减少透明度下仍可阅读操作；笔记长文滚动流畅。
- [ ] 可选 Liquid Glass 不遮挡内容，若 Wails/macOS 实机不稳定，能降级为实色/标准系统材质；不以玻璃效果为 MVP 必备条件。
