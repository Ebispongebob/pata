# 阶段 16 · Notes 左右分栏与草稿体验 — Idea

> 状态：**产品方案已确认，待实施**（2026-10-26）。本文件记录用户裁决；实现细节与验收以 [proposal.md](proposal.md) 为准。此前 15 阶段为应用内更新，本阶段编号为 16。

## 为什么做

当前 Notes 是「单列卡片浏览 → 进入全区域编辑 → 返回列表」；在多篇笔记间切换成本偏高，尤其不适合同时暂存多条未整理的记录。用户需要多张能独立、长期保存、随时回看的草稿，而不是单张用完清空的便签。

**产品原则：Less is More / Record Once / Local First。** 记录时不要求预先命名与分类；值得整理时，给同一份内容命名即可成为正式笔记。

## 核心决策

1. **导航不变**：仍只有 Today / Tasks / Notes。Notes 工作区内部改为「左侧列表 + 右侧编辑器」；这不是新的 App Shell 级 Inspector，也不新增第四导航。左列表可拖拽调整宽度和收起；右侧只有一个编辑器，暂不做 VS Code 式 Tab。
2. **左列表上下分组**：上方「草稿」，下方「笔记」。草稿**没有标题**，列表显示正文开头最多两行；正式笔记只显示标题，不显示摘要。两个分组可独立折叠。
3. **默认创建草稿**：Notes 主「+」直接创建草稿、焦点落入正文；下拉菜单保留「新建笔记」及「从音频创建逐字稿」。草稿没有标题、标签输入区域，也不展示时间和「我/Agent 创建」标记；正常自动保存状态不打扰，失败/冲突才提示。
4. **草稿是持久化 Note**：可以有多条，可以长期保留；不引入单独 Draft 实体、Inbox、临时目录、自动过期或强制整理。新草稿有内容后落盘，空白且从未保存的草稿离开可放弃；已落盘草稿即使清空正文也不应被默默删除。
5. **草稿 → 正式笔记，单向转换**：在右侧点击「转为笔记」后，**不弹窗、不跳页**，原地切换到正式 Note 的标题/标签/正文布局，**立即聚焦标题输入框**。正文和编辑位置不变；输入非空标题并成功自动保存后，正式完成转换并移入「笔记」分组。标签可选，随时补充。未填写标题就离开仍是原草稿。**不存在正式笔记转回草稿**。
6. **原文件保留**：转换只修改同一 Note 的元数据，不创建第二份正文，保留原 Note ID、创建时间、附件与引用关系；不因转换改动存储路径/文件名，避免破坏 Markdown 相对链接。
7. **排序统一而独立**：草稿和笔记各自按 `updated_at` 倒序；并列时按 `created_at` 倒序，再按 ID 稳定兜底。编辑中的自动保存不能导致左列表不断跳位；离开当前编辑对象/重新进入列表时更新排序。
8. **搜索和导航统一**：草稿参加全文搜索；搜索结果、任务/活动中的笔记链接和左列表均在 Notes 的**同一个右侧编辑器**打开；左列表自动展开并定位目标。搜索浮层再次打开时可恢复上次关键词和结果，避免重复输入。不增加搜索专用编辑视图或 Tab。
9. **引用边界**：草稿可以在正文里链接现有笔记与附件，但**不加入其他页面的 `[[Note]]` 目标候选**。正式命名后按现有笔记引用机制使用；已有正式笔记和历史链接不能被错误重绑定。
10. **必要元信息仍存储**：草稿 UI 隐藏时间和来源，但底层保留 `created_at` / `updated_at`、稳定 ID；现有可选 `created_by: agent` 规则不变，转换不改变创建来源。草稿不提供标签；正式笔记标签仍为可选。

## 用户体验一句话

**点击 + 就写；左边找，右边写；想整理时点「转为笔记」，直接输入标题，就完成了。**

## 不做

- VS Code 式 Tab、预览/固定 Tab、编辑器多窗格、独立速记悬浮窗。
- 草稿反向转换、状态工作流、手动排序、置顶、批量整理、自动归档与过期清理。
- 为搜索结果另建列表/编辑器、为草稿另建业务实体或单独存储目录。
- 保存成功的重复提示、草稿标题/标签/时间/来源常驻 UI、转换确认弹窗。

## 交付边界

本阶段包含**草稿存储支持 + Notes 内部分栏 + 转换交互 + 搜索导航回归**；对正式 Note、只读音频逐字稿、Today/Task/Activity/全局 Inspector 的既有行为保持兼容。详见 [proposal](proposal.md)。
