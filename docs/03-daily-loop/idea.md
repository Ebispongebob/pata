# Idea — 阶段 3：跑通每日工作闭环

**阶段目的**：让任务从“待办列表”进入真实的工作日，并在执行过程中自然留下记录，不增加额外的工作日志或日终打卡。

**阶段产出**：可排序 DayPlan、历史 Today、独立与任务关联的 Memo、任务完成事件时间线；补齐带标签快速创建、原地打开任务详情与修改属性的日常操作体验。

## 当前基础与本轮反馈

阶段 3 的 Memo、DayPlan 和历史时间线基础已实现。本轮根据 [查看 Today 页面](chatgpt-conversation://6acde6d4-264c-83e9-95ef-86aca343d135) 的使用反馈，完善已有页面，不新增实施阶段。

用户明确希望创建任务时直接输入 `#标签`，并且**只识别末尾连续标签**：先写完整任务名称，再添加标签。另一个实际阻碍是 Today 新建任务后不能从计划行打开详情，无法顺手补充描述、修改属性。本轮确认移除任务优先级，用计划顺序表达当天推进次序。

原讨论还提出压缩日期和空状态、弱化文件路径与重新扫描、简化时间线等建议。本轮将其整理为待实施方案；原对话截图未包含在可读取记录中，不据此宣称像素尺寸或实机视觉已经验收。

## 今日计划为什么存在

每天打开第一眼知道要做什么，也能看到当天有价值的进展。不是日历、日报或独立任务池。

**只包含两个主要模块：今日计划 / 今日记录。**

## 统一记录为什么存在

随手记录一句有价值的话；既是独立记录，也是任务评论。不再单独建设日志实体。

## 先写任务，再加标签

输入 `完成资源管理设计 #工作 #架构`，一次提交即可得到标题和标签。Today 与 Tasks 使用同一输入规则，区别只在 Today 还会安排到当前查看日期。

末尾 `#` 提供已有全局标签建议；新名称随任务保存进入标签聚合。快速创建不增加常驻标签选择框，也不要求预先管理标签。任务名称中间的 `#架构` 保留原文。

## 在 Today 完成任务操作

采用类似 ChatGPT 的三栏布局：**左侧主导航 / 中间 Today 或 Tasks / 右侧任务详情**。点击任务名称或行内空白打开右栏，中间计划或任务列表继续可见、可操作；关闭右栏后中间内容恢复空间。Today 与 Tasks 复用同一个详情面板，沿用现有描述、Memo 和显式 Note 关联能力。

右栏按需打开，各内容栏独立滚动；窄窗口按可用空间收起导航或展示可返回的详情。Notes 继续单列浏览、全主区域编辑。“移出今日计划”明确表示取消当天安排。任务本身始终只有一份，修改会反映在 Tasks 和其它引用该任务的页面中。

## 内容优先的日常工作台

打开 Today 首先看见日期、计划和记录。日期导航与空状态保持紧凑，列表随内容增长；Memo 输入靠近时间线顶部，手动记录与任务事件用时间、图标和简洁文字区分。

单 Vault 的路径与维护操作收至现有全局入口，异常仍可见。尊重系统强调色，减少重复边框和大面积色块，不把 Liquid Glass 当作交付前提。

## 本轮交付结果

- Today / Tasks 均支持末尾多标签输入、补全和新标签保存，标题与标签分别落盘。
- Today 可直接打开共用任务详情，修改状态、标签、due、描述，继续使用已有 Memo 与 Note 关联。
- 完成、排序、移出计划各自含义清楚；保存后各页面显示同一任务的最新属性。
- 日期、空状态、输入与时间线更紧凑；历史完成事实、DayPlan 与 due 的独立性保持可验证。

实施顺序、边界和待验收项见 [proposal.md](proposal.md)。不增加标签实体、日志实体、任务副本、强制复盘或新的主导航。
